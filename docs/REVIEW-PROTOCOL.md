# 审查协议（强制）— 嘉的要求

**手册是唯一规格来源。** 本仓库实现必须严格对齐《探店规划 Agent 计划手册》。
`PROJECT_IMPLEMENTATION_PLAN.md` 里的 Δ 条目分两类：

- **事实性勘误**（工具数量、ECE 数值、迁移脚本幂等、pom 硬钉…）→ 直接照修，
  因为修完更贴近手册本意。改完须在 Δ 表里写明依据。
- **偏离手册的决定**（改动交付顺序、提前做 HTTP 通道、跳过某阶段）→ 标注 **`待批准`**，
  **未经嘉点头不得落地实现**。

## 小任务粒度

一个任务卡 = 一个可独立验收的目标（例：「MCP 客户端握手可用」）。
**每完成一个小任务，必须自审一遍**，结论写进该任务的 `SELF-REVIEW-<卡号>.md`。

## 至少三遍审查，缺一遍不许进下一个任务

| 遍次 | 谁审 | 审什么 | 产出 |
|---|---|---|---|
| 第 1 遍 | 执行器**自审** | 对照任务卡「实现要求」逐条自查；跑通全部验收命令；列出自己没做到/降级的点 | `SELF-REVIEW-<卡号>.md` |
| 第 2 遍 | **异源模型只读复核** | ①安全 ②逻辑正确性（逐条对照任务卡）③边界条件（空输入、异常路径、并发）④有无自作主张发挥 | 审查报告，落盘 `docs/reviews/<卡号>-review.md` |
| 第 3 遍 | **管理者验收** | 独立重跑验收命令 + 全量回归；逐条核任务卡；确认前两遍结论是否成立 | 验收结论，落盘 |

第 2 遍的异源规则：DSH 产物 → Codex 审；Codex 产物 → DSH 审。**审查者只读不改。**
发现问题 → 打回原执行器重做并记录轮次；**两轮不过 → 升级人工决策**。

## 回归红线

任一遍发现基线被破坏（`mvn -B -ntp verify` 掉测试，或秒杀/登录/关注/点赞/签到/GEO 任一受损），
**立即打回，本任务不计完成**。

## 小任务完成定义（DoD）

三件事同时成立才算完成，缺一不可：

1. 任务卡「验收命令」全部真跑通过，输出留证；
2. 三遍审查全部通过，记录齐全并落盘；
3. `mvn -B -ntp verify` 仍为 **28 tests 全绿**（或更多且无新增失败）。

**禁止**：为让审查好看而调整测试断言；只写 happy path；
在自审里隐瞒未达成的条目。
